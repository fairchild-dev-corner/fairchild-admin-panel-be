# CLAUDE.md

See README.md for commands, endpoints, tables and known gaps.

- Go API for `../fairchild-admin-panel` (Next.js, port 3001). Runs on **port 8081**; port 8080 is fairchild_be (members). Don't start or kill anything on 8080 or 3000.
- Mirrors fairchild_be's structure: `cmd/main.go` → `config.ServerConfig` → `cmd/api/api.go` `Run()` wires each feature as repo → service → handler by hand. New features follow the same split, with the repository interface in `internal/interfaces`.
- Shares the central auth DB (`fccmpc_coop_auth_central`) with fairchild_be. Only create or alter tables this service owns (see README "Tables"). Never ALTER fairchild_be's tables; use a side table like `membership_application_reviews`. The only writes to them are `membership_applications.status`, the pending-row INSERT behind `POST /admin/membership-applications`, and behind `/admin/portal-members`: adding an account (`users` + a password-less `user_account_cred`), the email/mobile update, the `status` change (plus revoking that user's `auth_sessions` when it becomes suspended), and the soft delete (plus revoking that user's `auth_sessions`); and behind `/admin/account-claims`: a claim's review fields (`status`, `rejection_reason`, `reviewed_at`), with approval also setting the matching `users` row's email/mobile, and deleting an approved or rejected claim; and behind `/admin/locked-accounts`: unlocking (`locked_member_accounts.is_locked = FALSE`, `unlocked_at`). Migrations are tracked in `admin_panel_schema_migrations`. Add new numbered pairs; don't edit applied ones.
- Branch ledger DBs are read-only and never joined with central-DB tables.
- Every `/admin/*` route sits behind `middlewares.RequirePanelAuth`. Admin-only routes add `middlewares.RequireRole(cc.ROLE_ADMIN)`. Every admin mutation writes `admin_audit_logs` via `audit_repo.InsertAuditLogTx` inside the same `database.WithTx`. The actor comes from `middlewares.ActorFromContext`, never from the request body.
- JSON field names must match `../fairchild-admin-panel/src/models/{admin,auth}.ts`.
- Errors: sentinel errors live in `internal/constants/error_constants.go`, are matched with `errors.Is` in handlers, and are written via `loggers.GetCommonError`. Successes go through `loggers.SuccessResponse`.
